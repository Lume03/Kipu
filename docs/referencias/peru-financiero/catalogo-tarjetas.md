## 1. Objetivo

Este maestro documenta productos de tarjeta de crédito para personas naturales emitidos u ofrecidos en Perú que se pudieron identificar mediante documentos fuente locales y fuentes oficiales en línea. Puede utilizarse como punto de partida verificable para poblar y mantener el catálogo referencial de Kipu. No constituye una cotización, recomendación financiera ni promesa de aprobación.

## 2. Advertencia sobre tasas

Las tasas de este documento son referenciales y cambian con el tiempo. Pueden depender de moneda, modalidad de financiamiento, plazo, evaluación crediticia, producto específico, canal, fecha de contratación o perfil del cliente. Una tasa publicada no es necesariamente la tasa que recibirá cada cliente.

La tasa personal que conste en la HRI/contrato vigente del usuario tiene prioridad sobre la tasa del catálogo. Kipu no debe presentar una TEA del catálogo como oferta individual ni usar una TCEA como TEA. Una tasa promocional de cuotas puede ser distinta de la tasa de compras rotativas y de la tasa de disposición de efectivo.

Reglas aplicadas:
- Se conserva cada rango, máximo, mínimo y condición literal disponible.
- TEA, TCEA, TEM, TNA moratoria y tasas de efectivo/cuotas se registran en campos distintos.
- Si solo existe rango, máximo, información variable o varias monedas, el canon deja la TEA única y los bps en null cuando no existe una única cifra representativa para el modelo actual.
- No se convierte TCEA a TEA. No se calcula promedio ni se elige el máximo de un rango.
- En caso de fuentes oficiales con valores diferentes se registran las dos lecturas y se deja pendiente la vigencia si no puede resolverse por fecha/versionado.
- “No disponible públicamente” significa que no fue posible verificar el dato en la documentación pública oficial consultada, no que el emisor carezca del dato.

## 3. Metodología

Investigación realizada el 2026-09-24. El usuario solicitó usar esa fecha como corte. Se revisaron recursivamente los archivos de la carpeta; luego se usaron sus nombres de productos y enlaces como pistas, no como evidencia automática de vigencia. Se hizo un barrido independiente por entidad y producto usando páginas, tarifarios, HRI, contratos, fichas y documentos alojados en dominios oficiales.

Jerarquía: SBS/BCRP para universo, regulación y estadísticas; sitio/documento contractual del emisor para oferta, tasas y costos; documentos oficiales de red para una pista de producto/emisor; fuentes secundarias no se usan para fijar tasas.

La revisión cruzada comparó el trabajo independiente de Codex con _review_agente_b.md de AGY. AGY reportó candidatos, omisiones y tasas; Codex reabrió fuentes primarias y rechazó cifras sin soporte suficiente. La última auditoría de AGY del archivo maestro se ejecuta después de la consolidación; sus hallazgos se documentan al final de la tarea y no se consideran correcciones hasta volver a verificarlos en fuentes primarias.

## 3.2 Alcance y unidad de conteo

Una fila de producto equivale a un nombre comercial/tier de tarjeta personal confirmado, incluyendo variantes de red explícitas, productos con garantía y tarjetas de negocio emitidas a personas naturales con negocio. Se excluyen adicionales, tarjetas empresariales/corporativas, débito, préstamos/avances asociados a una tarjeta y beneficios promocionales. Un producto con red no identificada se marca UNKNOWN y no se duplica en Visa/Mastercard. Los productos cuyo documento solo prueba existencia histórica o cuyo estado de venta actual no se pudo confirmar no forman parte del total vigente.

La lista SBS se utiliza como universo de instituciones supervisadas, no como lista de emisores de tarjetas. La pertenencia a SBS o al registro de participantes de una red de pagos no basta para incorporar una entidad: debe existir evidencia específica de tarjeta de crédito personal.

- Revisar catálogo y páginas de emisores trimestralmente; volver a descargar HRI/tarifario al menos cada seis meses y ante avisos de cambios de precios o productos.
- Revisar mensualmente tasas, TCEA, seguros, membresías, conversiones de moneda, comisiones por efectivo, cargos por mora, requisitos de venta y productos nuevos/cerrados.
- Mantener fuente, fecha de publicación/revisión, fecha de vigencia, fecha de consulta, moneda, modalidad (rotativo/cuotas/efectivo), rango y condición “máxima/después de evaluación”.
- No guardar una TEA genérica en credit_products si existen varias monedas, rangos o tasas asignadas individualmente; considerar columnas por moneda/tipo de operación y rangos min/max. Mantener la tasa contractual del usuario en la tarjeta personal como dato separado y de mayor prioridad.
- Cuando se tenga documento nuevo, cerrar el intervalo previo con effective_to y abrir la nueva versión con effective_from; no sobrescribir historia. Guardar el documento/URL en historial de fuentes y un hash del archivo descargado.
- Ejecutar monitoreo automático de enlaces, pero confirmar cambios de contenido manualmente; un HTTP 200 no demuestra que el documento sea la versión vigente.
- Versionar con fecha/corte, registrar quien revisa, comparar diferencias de texto/tasas entre versiones y conservar snapshot de HRI/tarifario.
- Mantener separados los estados VIGENTE, VIGENTE LIMITADO, PENDIENTE DE VERIFICACIÓN y DESCONTINUADO; el UI no debe mostrar históricos como opciones solicitables.
- Usar una tarea de mantenimiento que contraste el dataset normalizado con el detalle por institución y alerte si un valor bps no equivale exactamente al porcentaje TEA de fuente.
